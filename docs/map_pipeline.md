# The regional world map

How the world map's painted canvas is made, and how to remake it when a zone opens or the art
changes. Spec #421; the client draws it in #424.

## Current M-key navigation map

The M-key world map is a continuous, world-coordinate navigation surface. It
uses the terrain survey at every scale. The rejected generated painting
`world-map-painted.png` is retained as a reference only and is never loaded by
the build. No city card or generated landmark can displace a road, building,
river or the terrain beneath a live marker.

Run `scripts/remake-world-map.ps1` to survey, assemble and package all three
layers. Rebuild the client to embed them. For an unchanged survey, run the
`map_region` example and package its outputs without extracting game data again.

- `world-map-geography.png`: since 2026-10-28, Davis's painting
  `world-map-painting.png` (1536 by 1024) upscaled to 5015 by 3343 by
  `import_art.py --size`, with no warp or fill. The survey's parchment version,
  generated by `examples/map_region/cartography.rs`, is kept as
  `world-map-geography-survey.png`. `remake-world-map.ps1` writes the survey
  version back over the painting; upscale the painting again after a remake.
- `world-map-detail.png`: the original survey sampled onto the same canvas grid.
  Buildings, streets, roads and water are sourced from the installed terrain
  bakes. This layer fades in from zoom 2 to 4, below exploration covers and fog.
- `world-map-exact-fog.png`: the independent closed-area fog from actual terrain
  areas. Burning Steppes remains held until opened in `map_canvas.json`. Since
  2026-10-29 the client draws `world-map-hush-fog.png` in its place.
- `world-map-hush-fog.png`: Davis's ChatGPT fog, painted over the 1536 by 1024
  painting with open land as the stock covers' union, upscaled to 5015 by 3343
  by `import_art.py --size`. It must be repainted when a zone opens.
- `world-map-names.png`: Davis's ChatGPT place names for the four open zones, on
  the same frame and upscaled the same way. The canvas plate draws it as ARTWORK,
  above the survey detail and below the exploration covers. Zone names stay
  live UI.
- `world-map-exact.png`: fogged overview preview.
- `world-map-region.json`: canvas bounds, layer provenance and validation.

All three layers are 5015 by 3343, packaged into 280 tiles each, using the same
world rectangle. Upsampling never creates additional survey detail; the source
bakes resolve about 2.08 yards per texel. Stormwind's detailed terrain stays in
its actual geographic position, without a separately scaled city illustration.

`WorldMapCanvas.xml` provides wheel zoom around the cursor and drag pan, with
eight times the widest zone's stock scale available for individual locations.
`WorldMapNavigation.xml` adds the terrain-detail transition, overview zone names,
category toggles for quests/services/dungeons, and close-zoom NPC names. Nearby
pins of the same type within 18 UI pixels share a count and tooltip containing
all their locations and descriptions. They separate automatically as zoom
increases. Grouping never offsets a marker from its world position.

The realm already provides the live marks: currently available quests and
ready hand-ins, service NPCs (vendors, trainers, innkeepers, flight masters), and
Phased Dungeon entrances. The map consumes that authoritative list; it does not
bake services or quest state into an image. Services with a quest use the quest
pin, as the realm's existing mark feed specifies. Filters affect presentation
only. The 76 exploration covers retain their alpha masks and UV rectangles.

Validation uses the actual shipped map scripts in the client UI harness, covering
zoom, pan, hover, marker position, clustering, category filters, terrain detail
and frame reuse. A full game visual check is separate from these automated tests.

## Terrain survey and original Stormwind reference

For the source survey and coordinates, use `data/twilights-eve/map/survey/index.html`.
The current game map uses this survey for both overview and terrain detail; the city map is a separate reference.
`scripts/remake-world-survey.ps1` reproduces the package from the local WoW Data folder.
It exports:

- `terrain-survey.png`: the installed client's original terrain minimap bakes in one
  orthographic world-coordinate projection. No painted fill or illustrated geography.
- `terrain-survey-playable.png`: the survey with fog over closed terrain areas.
- `terrain-survey-fog.png`: the independent RGBA fog mask.
- `Stormwind.png`: the complete original stock 1002 by 668 city map, including its backdrop,
  districts, streets, labels, and original frame. It is not cut out or warped.
- `survey.json`: world bounds, projection, source hashes and native resolutions, authoritative
  AreaPOI world-coordinate markers, coverage statistics, and numerical validation.
- `index.html` and `survey-data.js`: a local pan/zoom viewer with a world-coordinate readout,
  100-yard grid, original Stormwind map alongside, and the approved necropolis annotation.

The raster is 6729 by 4486, approximately one yard per output pixel. The 126 original
terrain minimap bakes contain 2.083333 yards per source texel, so upsampling does not
produce yard-level imagery detail. Numerical coordinate projection round trips are
checked at 10201 points and must remain below one millionth of a yard; the observed
maximum is about 0.000000000002 yards. These are coordinate-transform checks, not a
claim that the source illustrations or terrain bakes resolve every feature to one yard.

Fog follows actual ADT MCNK area IDs and their AreaTable zone ancestry. Unknown areas
remain closed; missing minimap tiles are explicitly uncharted, never filled with invented
land or assumed ocean. The current build has no missing playable source pixels.
Only POIs on playable terrain are exposed in the viewer. The necropolis is a custom
annotation at the centroid of the terrain's Twilight Grove area, identified as such;
no verified necropolis world-model placement currently supplies an exact position.

The previous pixel-preservation validation only established that existing map pixels
were unchanged. It did not establish yard-accurate placement of painted features.

## Original painted pipeline: reference only

The following documents the earlier illustrated canvas and its tools. Use the current
regional rebuild above for the game; the original `canvas.png` stays unchanged.

### Where things live

- `data/twilights-eve/map/` is the source of truth: the original `canvas.png` (5015 by 3343), one
  `fog_<file>.png` per misted zone, `covers/` (one per stock exploration overlay piece) and
  `manifest.json` (each file's pixel size and its rect in canvas UV). No tool writes here; a
  remake is copied in on purpose.
- The active map now uses `world-map-geography.png` (the approved necropolis edit) and
  `world-map-exact-fog.png` (one continuous closed-region fog layer). Their 256 px TGA
  tiles live in `crates/benilla-app/assets/ui/map/` and are compiled into the client.
  `world-map-exact.png` is the combined full-map preview. Keep the original `canvas.png`
  unchanged as the repeatable build source.
- `data/twilights-eve/map/fill_painting.png` is Davis's ChatGPT painting, and
  `fill_landmarks.json` pins it to the canvas.
- `data/twilights-eve/map_canvas.json` lists the open zones (`zones`, in draw order) and the
  zones the canvas holds in full while they stay misted (`held`). The canvas rect is the union
  of both, padded to 3:2, in the client (`canvas_view` in `crates/benilla-app/src/ui_world_map.rs`)
  and in the tool alike.
- `crates/benilla-formats/examples/map_draft.rs` is the tool.

### Remaking the original illustrated canvas

    cargo run -q --release -p benilla-formats --example map_draft -- --data C:\Users\davis\wow-data\Data --out target/map_draft --fill data/twilights-eve/map/fill_landmarks.json > target/map_draft_run.txt

Redirect the output to a file rather than piping it into `head`, which kills the run before it
writes. It writes under `target/map_draft/`:

- `filled.png`: the finished canvas. The stock zone maps sit at their true places, and the
  painting is warped into every gap between them.
- `filled_preview.png`: the same with every fog on it, as a player sees it today.
- `landmarks.png`: the warped painting alone, with a red cross on each landmark's canvas point.
- `canvas.png` (the stock-only draft), the fogs, the covers and `manifest.json`.

Then copy `filled.png` over `data/twilights-eve/map/canvas.png`, and the fogs, covers and
manifest over theirs, unedited. Check every spot you changed at full size with
`scripts/img.ps1 crop`, since the Read tool shows a 5015 px image at 40%.

### The fill file

`fill_landmarks.json` has three lists, all in UV (0 to 1 from the top left):

- `pairs`: the same place on the canvas and on the painting, usually a label's centre. Measure
  both with `scripts/img.ps1 crop -Scale 4 -Ticks` rather than on a scaled-down view. The run
  prints each pair's leave-one-out error, worst first, and flags any over twice the median:
  re-measure a flagged pair, or accept it where the painting itself drifts (Moonbrook, Eastvale
  Logging Camp, Stonecairn Lake and the Temple of Atal'Hakkar flag today for that reason).
- `erase`: a box of the painting and an offset to copy land from, for a painted label or icon
  that shows past the stock art. Painted lettering is larger than stock, so a painted label near
  a zone's edge pokes out beside its stock twin.
- `keep`: a box of the canvas where the stock art stays solid, for a stock label its own zone's
  silhouette clips (the F of Forest's Edge).

### Opening a zone in the legacy painted canvas

Move its id from the misted set into `zones` in `map_canvas.json`, remake, and check its edges:
painted labels it kept under fog now show. Add `erase` and `keep` boxes until none do. A zone
that is neither in `held` nor inside the canvas rect grows the rect, and then the painting needs
to cover the new area and every landmark moves: plan that as its own ticket.

### A new painting

#### Legacy pixel-preserving illustration build

`target/map_exact/exact.png` is the old pixel-preserving illustration revision.
It retains the shipped canvas's 5015 by 3343 pixels and world rect. The fully clear
pixels are copied unchanged, including the actual stock Stormwind city layout.
It does not redraw or re-warp the existing geography. Existing connecting fill
art remains from the shipped canvas; it is not a newly invented geographical map.
Only the central Twilight Grove clearing is edited to show a necropolis.

Rebuild with:

    cargo run -q --release -p benilla-formats --example map_draft -- --data C:\Users\davis\wow-data\Data --out target/map_exact --exact

This uses `canvas.png` as its unchanged geographical source and
`necropolis-patch.png` (built-in image_gen output) for the local landmark edit.
Only pixels inside `[1925,2435,2135,2620]` can receive the generated landmark.
The full prompt is recorded in `map/necropolis-patch.prompt.txt`.

`exact.png` has fog baked for the current `map_canvas.json` playable zones.
`exact_fog.png` is the separate full-canvas RGBA fog layer, derived from the
stock playable zone silhouettes in world coordinates. Its outside is opaque;
the playable boundary is feathered, with continuous canvas-space cloud noise.
The mask extends the coarse zone highlights to keep connecting rivers visible.
`exact_validation.json` records dimensions, coordinates, and a full pixel check:
every completely clear pixel outside the local edit must match the source.
These outputs are historical references. Do not copy them over the active regional map.

The active client consumes `world-map-geography.png` plus the separate
`world-map-exact-fog.png`, each in 280 tiles. `WorldMapCanvas.xml` draws the full-canvas
fog plate above the exploration covers and geography. `WorldMapMist.xml` suppresses
the old additive zone Highlights only while this canvas is active. Other map views
retain their existing mist. Exploration-cover alpha masks and the existing manifest UV
rect remain unchanged. Rebuild when a zone opens.

Use `scripts/remake-world-map.ps1` to rebuild, validate, copy the final PNGs, and
package both layers into client tiles. It requires Cargo, the local WoW Data folder,
and Python (or uv with an installed Python). It never overwrites `canvas.png`.

ChatGPT redraws the whole image on every edit and cannot hold positions; asking it to trace the
draft moved places by 100 to 600 yards. Ask it for what the warp can use instead: show more land
past every edge (zoom out), or remove something (Stormwind's own city, so the stock city lies on
land). An edit that only removes usually keeps the rest pixel for pixel; check with
`scripts/img.ps1 compare` before reusing the landmarks, and re-measure them if anything moved.

### Legacy Stormwind cutout (not used in the current regional map)

Stormwind's Highlight is black, so the city is cut out by a flood from its card's frame: the
flood takes the plain backdrop and stops at the ink outlines round the walls, districts and
crest (`FLOOD_STEP`, `FLOOD_REACH`). The city also clears Elwynn's art under it, so Elwynn's own
drawing of the city does not show between the districts. The painting must have no city there.
